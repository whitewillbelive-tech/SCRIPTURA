# SCRIPTURA 구현 수용 기준

## Gate S-0 — 프로젝트 시작 (이 패키지)

- 표준 초안·DB 스키마·소스 정책·샘플·검증기·Work/Codex 프롬프트 존재
- 패키지 자체 테스트 완료
- 실제 대외 수집/배포나 기존 프로젝트 수정 없음

## Gate S-1A — 학술·자료원 설계 (Work 주도)

- 최소 12개 자료원 후보 등록. 최소 5개는 공식/1차 출처, 5개 이상은 학술 서지 또는 주석 자료
- 각 자료원마다 접근/저장/변형/색인/재배포 권리와 라이선스·약관 URL·검토 날짜 기록
- 복수 정경/장절 체계의 주소 매핑 검증 케이스 최소 10개, 그 중 비동등·부분대응 사례 포함
- 시범 구절 2개 선정 및 1차 문헌 후보와 해석·반론 목록 정리
- 개인 견해와 기관의 공식 문서 간 혼동 0건
- 저작권 불명 자료는 메타데이터만 추출

## Gate S-1B — 데이터 엔진·기본 탐색 (Codex 주도)

- 별도 저장소에서 PostgreSQL DDL 적용/롤백, 릴레이션 무결성 테스트
- 권/장/절 검색이 기준 주소 체계를 선택해 동작
- 본문·전통·주장·출처·검증 상태에 대한 검색 API
- 관계도 시각화 데이터 API로 주장→증거→반론 방향성과 출처 확인 가능
- '공식 교리'와 '개인 의견'을 동일 라벨로 묶지 않음
- 가짜 원문 및 허위 출처를 방지하기 위한 데이터 검증 계층
- 사용자가 검증 대기·저작권 상태를 화면에서 확인 가능
- 인증·관리자 승인·감사 로그; 운영 공개 및 실제 사용자 계정은 별도 결정
- 테스트 PASS 결과, 미완료/제한 사항 보고

## Gate S-2 — 실증 2개 본문과 연구 AI

- 시범 본문 2개에 대해 서로 다른 전통의 원전 근거 확인
- 출처에 대한 정확한 위치 링크와 내용 대조 100%
- 특정 견해에 대한 근거·반론 경로가 화면에서 열림
- AI 결과에서 허위 인용 0건, 사용 출처가 실제 검색 결과에 존재
- 출처가 불충분할 경우 `insufficient_evidence` 처리
- 같은 질문을 다른 판정 모드로 질의해 전제에 따라 달라지는 부분 표시
- 인적 평가 절차 및 수정 이력 검증

## 진행 원칙

Gate별로 PASS/FAIL/보류를 기록한다. 테스트 PASS를 학술적 사실 확정이나 사이트 운영 승인으로 오인하지 않는다.
