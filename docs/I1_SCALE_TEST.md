# I-1 복합 합성 규모 검증

이 검사는 실제 연구 ZIP과 PostgreSQL을 사용하지 않는다. `scripts/benchmark_i1.py`는 완전히 허구인 D-2 기준 및 D-3 delta·병합 ZIP을 임시 디렉터리에 생성하고 폐기한다. 소스 행만 반복하지 않고 각 번들에 자료원·판본·정확히 9개 행위별 권리·위치·두 본문·대응·연구자 소속·두 주장·근거·검수 이력·주장 관계·서지 인용·정경 커버리지를 함께 생성한다. `allowed`, `conditional`, `unknown` 권리 판단이 있어도 이 브리지에서 9개 행위 모두 기본 거부되는지 검사한다. 실제 인적 검수나 자료원 권리, 의미의 진위를 입증하는 시험이 아니다.

```sh
python3 scripts/benchmark_i1.py --records 10000
python3 scripts/benchmark_i1.py --records 100000
```

기준선 해시와 기대 건수 override는 내부 합성 시험 호출에만 쓰이며 실제 D-3 CLI에는 공개되지 않는다. 각 실행은 생성과 검증을 독립 프로세스로 분리해 wall time과 최대 RSS를 기록한다. `--records`는 목표 최소 행 수이며 12종 병합 테이블 및 별도 인용·커버리지 행의 합계가 이를 넘도록 번들 단위로 반올림한다.

이번 클라우드 실행에서 10,381 합성 행 및 103,855 합성 행이 검증을 통과했다. 103,855행은 자료원 7,696, 판본 3,843, 독립 권리 34,587, 주장과 근거 각 7,685, 주장 관계 3,842, 서지 인용 3,853, 커버리지 3,922 등을 포함한다. 정확한 소요시간과 최대 RSS, 각 데이터 종류별 건수는 [10k 결과](../reports/i1-benchmark-10k.json), [100k 결과](../reports/i1-benchmark-100k.json)를 참조한다.

이는 단일 클라우드 인스턴스에서 실행한 허구 자료의 ZIP 생성·읽기 검증 측정이다. 분포는 동일한 인공 번들의 반복이며 실제 학술 데이터 특성, 다중 클라이언트, 적대적 동시성, PostgreSQL 쓰기 성능 또는 운영 서비스 처리량을 예측하지 않는다. 부하 생성 및 검증 모두 메모리에서 전체 레코드를 구성하므로 대규모 자료에 대한 스트리밍·자원 한도와 별도 부하 검증이 필요하다.
