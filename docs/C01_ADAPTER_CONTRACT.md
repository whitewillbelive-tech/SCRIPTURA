# C-01 공통 수신 진입점

`scripts/c01_receipt_adapter.py`의 `receive_increment`는 입력 형식을 명시적으로 선택하는 폐쇄형 진입점이다. `legacy_work_d13_d16`은 기존 `k37_bridge.real_receipt.load_d16_archive`를 그대로 호출해 고정 원본 해시·계보·참조·권리 및 기존 비공개 화면 정책을 보존한다. 그 결과는 기존 비공개 탐색기에만 제공하며 원본이나 정본 DB를 쓰지 않는다. `jsonl_v1`은 외부 신뢰 앵커를 가진 단일 프로세스 `ResearchCatalog`로 기존 K3 매니페스트와 JSONL을 검증·격리해 메모리에 통합한다. 미지원 형식이나 서로 섞인 매개변수는 거부하며 다른 형식으로 자동 재시도하지 않는다.

반환 결과의 `aggregate()`는 고정된 건수와 검증 집계만 제공한다. `local_preview()`는 Work 전용의 기존 비공개 탐색 결과이며 민감할 수 있으므로 로그·공개 저장소·외부 모델에 보내면 안 된다. 일반 JSONL 결과에는 비공개 탐색 결과가 없으며, 수신 성공은 권리 승인이나 학술 검증을 뜻하지 않는다.

두 경로는 **정본 표현이 동일하지 않다.** 기존 Work 탐색 결과는 권리별 표시 정책을 적용한 투영과 봉인 인덱스이며, 모든 원본 식별자와 D15/D16 검토·권리 행을 일반 스키마로 내보내지 않는다. 따라서 이 결과를 역변환하여 `ResearchCatalog`의 완전한 정본이라고 주장하거나 자동 승격하지 않는다. Work 원본의 모든 관계·권리·판본·계보를 보존하는 공통 정본 변환기, 충돌 정리, 영구 저장과 다중 프로세스 조정은 별도 검증을 필요로 한다. 지원되지 않는 신규 JSONL 형식은 임의로 허용되지 않는다.
