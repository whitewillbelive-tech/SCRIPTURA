# C-01 연구 증분 수신 및 프로세스 내 통합 계약

`scripts/c01_receipt.py`는 기존 K-3의 `scriptura.research-archive.v1` ZIP/JSONL 검증기를 감싼 별도의 로컬 메모리 관리자다. 신뢰된 기준 스냅샷의 버전·전체 레코드를 하나의 정규 JSON 바이트열로 직렬화하고, 별도 신뢰 경로에서 얻은 SHA-256과 비교한다. 그 동일 스냅샷으로부터 참조 검사용 ID 맵을 만들므로 해시와 ID 맵이 서로 다른 기준본에서 왔을 가능성을 제거한다. 신뢰 해시를 ZIP에 있는 선언만으로 결정해서는 안 된다.

증분 매니페스트의 해시 역시 외부에서 인증해야 한다. ZIP 크기·경로·중복 멤버·압축률·해시·스키마와 ID·참조 검사는 기존 K-3 수신기를 사용한다. 오류 레코드와 종속 항목만 격리하며 정상 기준본은 변하지 않는다. 전부 격리된 비어 있지 않은 증분은 세대를 전진시키지 않는다. 동일 ID 충돌은 격리하고, 같은 제목·DOI는 병합이 아닌 중복 후보로 집계한다. 주소 체계를 추정해 통합하지 않는다.

검증은 사본에 수행하고 커밋 시 기준 해시를 다시 비교한다. 동일 관리자 객체의 동시 쓰기에서는 하나만 성공하며 다른 요청은 `baseline_changed`로 실패한다. `snapshot()`은 개인 정보가 들어갈 수 있는 로컬 사본이다. 공개 로그, 모델 입력, 클라우드, CI에 넣지 않는다. 역직렬화한 원본 내용을 로그나 예외에 쓰지 않고 원본 ZIP도 변경하지 않는다.

이 관리자는 **단일 프로세스, 단일 인스턴스**에서만 원자적이다. 여러 프로세스·PC 간 조정, 충돌 복구를 위한 영구 정본 저장, 권리 검토, 배포 승인, 사람의 학술 검증 및 데이터의 진실성 판단은 구현하지 않는다. 정본 수신 성공은 공개·AI 전송·원문 보관 허가가 아니다. 앱 또는 운영 DB에 자동 반영되지 않는다. 안전한 다중 프로세스 운영에는 별도 트랜잭션 저장소, 권한 제어 및 검증이 필요하다.

기존 동결 D-13/D-14~D-16은 현재 `k37_bridge.real_receipt` 경로로 처리된다. 이 Work 고유 포맷을 일반 매니페스트로 변환해 새로운 관리자의 증분으로 연결하는 범용 변환기는 아직 제공하지 않는다. 서로 다른 형식의 첨부 파일이 일반 계약을 만족한다고 가정하지 않는다. 신규 JSONL 작업은 사전에 합의된 매니페스트와 신뢰 앵커가 있어야 한다.

수신기의 `accepted`는 형식과 기계적으로 표현된 참조 검사를 통과했다는 의미이며, 공식 채택·발화자 귀속·직접 반박의 실증이나 학술 검증을 뜻하지 않는다. 특히 관계 레이블을 출처 확인 없이 확정된 반박으로 출력해서는 안 된다. 기준본 ID의 유형 외에 기준본 내부 사슬의 의미는 이 일반 수신기가 별도 검증하지 않으며 `baseline_semantics_unverified` 집계를 확인해야 한다.
