# K-1 연구 자료 출력 경계

## 이전 사고와 범위

J-3에서 D-8 수신 함수의 두 번째 반환값을 오류 집계로 오인한 뒤 구조체 자체를 도구 출력에 포함했다. 실제 메타데이터가 모델 문맥에 전달됐고, 전달 분량은 잘려 정확한 범위를 확정할 수 없다. 당시 모델 문맥에서 이를 되돌리거나 삭제할 수 없으며 이 사고는 J-3 `RESEARCH_BOUNDARY`의 FAIL로 보존한다. 코드 수정이나 시험 통과가 과거 사고를 없애지는 않는다.

K-1 점검 중 기존 공개 코드에 있던 아카이브 무결성 상수도 코드 조회에서 도구 출력에 포함된 별도 절차 이탈이 있었다. 새 연구 레코드를 출력한 경우는 확인되지 않았다. 이후 소스나 자료 파일은 필요한 부분만 제한적으로 검토하고, 무결성 값 자체는 출력하지 않는다.

## 후속 방어

- private layer의 반환값은 이름 있는 캐리어로 구분한다. 최상위 layer와 보조 매핑의 문자열 표현은 고정된 가림 표시이며 일반 JSON 직렬화를 허용하지 않는다.
- 민감 데이터 오류 집계는 정확히 허용된 `Counter`와 고정 오류 키만 받는다. 일반 dict나 예상 밖 키는 고정 오류로 거부한다.
- private layer reader 실행 중 Python 표준 출력·오류 출력으로 실수로 내보낸 값을 폐기하고, reader와 archive의 예외는 고정 오류 코드로 치환한다.
- `safe_diagnostic`은 사전 정의된 이름의 제한된 비음수 정수 또는 불리언만 직렬화한다. 실제 값, 사용자 정의 키, 문자열, 예외와 중첩 데이터는 거부한다. 집계의 입력값은 호출자가 연구 레코드와 분리해 계산해야 한다.
- 합성 sentinel로 직접 출력, JSON 직렬화, 오류 키 위장, 예외·traceback과 stdout/stderr 경로를 시험한다. 테스트와 로그에는 합성 값만 넣는다.

## 사용 절차와 한계

실자료 검사와 진단에는 **고정된 집계 또는 불리언만** 출력한다. 레코드·이름·식별자·URL·파일 경로·원문·자유 메모·원시 해시·예외 객체를 출력하거나 캡처하지 않는다. 예를 들어 Python 객체나 JSON 전체, 무제한 소스 파일 덤프, ZIP 내부 목록, 데이터가 든 명령어 실패의 상세 traceback을 도구 출력에 보내지 않는다. 출력을 발생시키는 명령은 실행하기 전에 고정 키와 형식을 확인한다. 실자료는 읽기 전용 메모리에서 처리하며 추출본을 로그나 Git에 기록하지 않는다.

불투명 매핑은 우발적 최상위 출력 방어이며 보안 샌드박스가 아니다. 중첩 값을 명시적으로 꺼내면 그대로 민감하고, `safe_diagnostic`의 숫자가 실제로 집계인지 코드만으로 증명하지 못한다. Python 표준 스트림 가림은 프로세스 전역이며 동시 콘솔 작업을 피해야 한다. OS 파일 디스크립터 직접 쓰기, 별도 프로세스, 디버거와 다른 도구의 출력은 차단하지 못한다. 따라서 실자료를 다루는 모든 검사와 도구 호출에 동일한 출력 절차가 필요하다.
