# K-3–K-7 실자료 수신 복구 기록

이 작업은 기존 K-2.1 연구 화면과 K-6 기능을 보존하면서 별도의 실자료 수신 감사 코드를 보강한다. 운영 DB 적재, 실제 연구 자료의 정본 자동 승격, 공개 배포와 `main` 병합은 수행하지 않는다.

## 원본 접근과 검증 상태

사용자가 제공한 정보에 따르면 관리 채팅에서 D-13 및 D-14~D-16의 연구 정본과 무결성, 기준본 및 증분 자료 검증이 이미 수행됐다. 그 사실과 이번 Codex 실행 환경에서 파일을 읽을 수 있는지는 별개다. 이 세션에는 ChatGPT Library 파일 조회 도구나 사용자가 지정한 작업 폴더의 마운트가 제공되지 않았다. 접근 가능한 파일과 중첩 ZIP을 읽기 전용으로 대조했으나 두 정본에 해당하는 입력을 확보하지 못했다. 따라서 관리 채팅에서 원본이 존재한다는 사실을 부정하지 않으며, **이번 실행 환경에서의 실제 수신·재검증만 PENDING**으로 둔다.

사용자가 알려준 D-13 출처·주장 각 47건, D-14 출처 96건·주장 98건·본문 45개, D-16 비교 묶음 80개는 이번 실행의 수신 결과가 아니다. 이 수치를 실제 탐색기 연결 성공으로 간주하거나 정본의 무결성을 이 실행에서 검증했다고 보고하지 않는다. D-13 기준본과 D-14~D-16 증분의 실제 ZIP·원문·사적 경로·연구자나 문헌의 식별정보를 저장소, CI 로그, 모델 출력에 넣지 않는다.

## 이번에 확인한 D-12 표시 보류 원인

기존 고정 D-12 연구자료를 읽기 전용 메모리로 확인하고, 원자료의 해당 안전 표시 판정과 개별 보류 사유를 대조했다. 전체 주장 44건 중 표시 9건, 보류 35건이며 기존 봉인 인덱스와 감사 집계의 불일치는 0건이다. 보류 35건 각각에서 다음 두 근거가 모두 누락돼 있다.

- 자체 요약 및 비인용을 확인하는 `verification_method` 표식이 없거나 비어 있다: **35건**.
- 원문 미저장을 확인하는 `original_text_stored` 필드가 없다: **35건**.

두 건수는 같은 35개 항목에 대한 **중복 사유**이며 70개 항목이 아니다. 이 결과는 해당 항목이 원문 인용이거나 법적으로 이용 금지라는 확정이 아니다. 반대로 누락만으로 자유서술의 표시 권리가 성립하는 것도 아니다. 원본 불변과 기존 표시 판정을 [비식별 실자료 집계](../reports/k37/d12-withheld-reasons.log)에서 확인할 수 있다. 관련 합성 감사 시험은 **8 PASS / 0 FAIL / 0 SKIP**이며 [로그](../reports/k37/d12-withheld-unit.log)에 기록한다.

## 완료 조건과 남은 통합

| 항목 | 이번 판정 | 확인 범위 |
|---|---|---|
| D-13 및 D-14~D-16 실제 수신 | PENDING | 정본의 관리 채팅 내 존재와 별개로 실행 환경의 Library 접근이 필요하다. |
| 기존 D-12 탐색·비교 | PASS | 실제 로컬 브라우저에서 기존 후보·검색·본문 비교·선택 및 문헌 연결을 확인했다. |
| D-12 미표시 35건 사유 | PASS | 기존 봉인 인덱스와 개별 사유의 결과가 일치한다. |
| D-13/D-14 주장·논거 표시 | PENDING | 실제 원자료별 자체서술·인용·출처·권리 및 개인정보 검증을 수행하지 못했다. |
| 공동체·발화 주체 귀속 | PENDING | 실제 신규 원자료의 관계·근거 연결이 필요하며 문헌 작성자를 발화 주체로 추정하지 않는다. |
| D-16 비교 묶음의 탐색기 연결 | PENDING | 실제 묶음과 본문 체계·판본에 대한 검증 및 화면 연결이 필요하다. |
| 원본 불변·보안 및 전체 CI | PENDING | 실제 신규 정본과 최종 자동 검증 결과를 별도로 확인해야 한다. |
| 이번 버전 Windows 사용자 수용 | NOT_RUN | 이전 버전의 Windows 수용 성공과 구별한다. |

복구 브랜치의 감사기는 실제 Work ZIP을 확인할 때 사용할 읽기 전용 도구다. 체크섬 목록의 개수·중복·단계별 모든 JSONL 데이터 파일 적용 및 일치, ZIP 경로·크기·압축비, 로컬 입력 변경과 중첩 기준본, 신규 테이블 간 ID 및 일부 출처·판본·위치·주장·근거 참조를 검사하도록 보강했다. 비데이터 문서 전체에 대한 체크섬 커버리지는 미확정이다. 오류 또는 의존 행의 **집계**를 제공하지만 정상 행을 UI에 연결하거나 실제 부분 적재하지 않는다. D-15·D-16 개별 관계 검증은 아직 미구현이며, 후속 비교 묶음의 건수 확인만으로 탐색기 연결이나 장절 대응을 입증하지 못한다.

합성 입력의 통과는 D-13/D-14~D-16 실제 파일과의 스키마 호환성 또는 UI 연결을 증명하지 않는다. 기존의 별도 v1 범용 수신 계약과 Work의 실제 중첩·증분 형식도 혼동하지 않는다. 독립 합성 보안 시험은 **15 PASS / 0 FAIL / 0 SKIP**이며 [로그](../reports/k37-recovery/independent-security.log)에 기록한다. 복구 코드의 나머지 테스트·제한 범위는 실행 로그 및 코드 문서를 따르며, 확인되지 않은 권한을 추정해 실제 데이터를 승격하지 않는다.

전체 Python 합성·기존 회귀는 **519 PASS / 0 FAIL / 0 SKIP**이며 [전체 로그](../reports/k37-recovery/python-all.log)에 기록한다. 실제 D-12 로컬 브라우저에서는 기존 528개 후보를 포함한 전체 621개 후보, 주소 26개·주장 44개·복수 주장 주소 16개·안전 후보 요지 9개를 확인했다. 제목·작성자 검색, 두 본문의 요지 6개, 해석 3개 선택과 탭 유지, 문헌에서 본문으로 이동, 인증·CSP·캐시·외부 요청 0·원본 불변이 통과했다. [실자료 비식별 로그](../reports/k37-recovery/actual-d12-final.log). 이 결과는 D-13과 D-14~D-16의 실자료 수용으로 환산하지 않는다. GitHub Actions 및 Windows 러너의 최종 결과는 개발 브랜치에서 별도로 확인한다.

Windows CI의 초기 합성 ZIP 보안 시험은 실패했다. Windows의 ZIP 생성 과정에서 역슬래시가 정규화돼 의도한 악성 경로가 시험 파일에 만들어지지 않았기 때문이다. 운영 감사기는 `ZipInfo.orig_filename`의 정규화 전 원본 경로도 검사하도록 보강했고, 시험은 ZIP의 로컬·중앙 디렉터리 파일명 바이트를 수정해 운영체제에 관계없이 같은 악성 입력을 생성하도록 고쳤다. Linux에서 Windows 경로 구분자 조건을 모의한 회귀와 합성 15건·전체 519건이 통과했으며, Windows 러너의 최종 결과는 재실행에서 별도로 확인한다.

기존 K-2의 Windows 사용자 수용 7/7은 사용자의 보고로 보존한다. K-2.1과 이번 복구 버전은 사용자 Windows에서 실행하지 않았다. 실제 환경에서의 안전한 최종 절차는 [Windows 통합 수용 안내](../K37_RECOVERY_WINDOWS_KO.md)를 참조한다. 기존 J-3 연구자료 출력 사고는 후속 시험으로 소급 복구되지 않는다.
