# S-1B.2 합성 규모 검증 계획

이 계획의 10,000건 및 100,000건은 자동 생성된 가상의 레코드다. D-2나 실제 문헌을 복제하거나 내용으로 부하 데이터를 만들지 않는다. 결과는 학술 자료 검증이나 운영 환경의 처리량을 의미하지 않는다.

## 구성과 측정

각 규모에서 테스트 전용 합성 패키지에 고유한 합성 ID를 부여하고, 12종 JSONL 및 전체 manifest 해시, 행 수, 외래키를 일관되게 생성한다. 가능한 경우 여러 개체와 연결·권리 행을 포함하고 권리 정책도 원래대로 적용한다. 참조 불능, 중복, 권한 없는 필드는 실패해야 하며 합성 판정 테스트가 통과해야 한다. 모든 파일은 테스트 종료 시 임시 디렉터리와 함께 삭제한다.

별도의 새 프로세스에서 `validate`와 `dry-run`에 대해 wall time, 초당 레코드 수, 최대 RSS 및 결과별 집계를 측정한다. 세부 레코드, 원문, 식별자를 콘솔이나 로그에 출력하지 않는다. 10k와 100k는 각기 새 생성·검증을 실시하여 파일 생성 시간을 검증 시간과 구분한다. PostgreSQL 격리 적재를 측정한다면 쓰기·읽기 역할을 분리한 빈 임시 `scriptura_staging_` DB에서만 명시적 opt-in으로 수행하고, 같은 snapshot 재실행에서 중복이 없음을 별도 확인한다.

기록할 항목: 날짜, OS/CPU/메모리, 런타임 및 PostgreSQL 버전, 행 수, 임시 ZIP 크기, 작업별 소요 시간, 최대 RSS, 반환 코드, 검사 및 격리 수, 건너뛴 단계와 이유. 성능 기준이 합의되지 않았으므로 임의의 처리량을 합격 기준으로 쓰지 않는다. 보안·무결성 실패, 누락, 예외 또는 비정상 종료는 규모에 관계없이 실패로 보고한다. 100k 측정은 시간·메모리 제약으로 실행하지 못하면 **SKIP**으로 명기한다.

기능 테스트와 부하 테스트를 구분한다. CI에서는 합성 소규모 계약·부정 테스트와 분리 권한 스테이징 테스트가 필수이며, 10k/100k 검증 시험도 합성 데이터만으로 별도 실행한다. 측정 속도 자체는 변동하므로 기능 검증의 통과 여부만 CI 기준으로 삼는다. 연구 D-2 ZIP은 CI에 추가하거나 업로드하지 않는다.

## 재현 및 현재 결과

프로젝트 루트에서 다음을 실행한다. 두 명령 모두 테스트 코드가 직접 만든 합성 ZIP만 사용하며 외부 파일 경로나 기대 해시를 입력받지 않는다.

```sh
python3 scripts/benchmark_d2.py --sources 10000
python3 scripts/benchmark_d2.py --sources 100000
```

2026-11-05 Codex 클라우드 Linux, Python 3.12.14, 표시된 논리 CPU 5개에서 실행했다. 10,000개와 100,000개의 가상 `sources` 각각에 적은 수의 합성 연관 행 18개를 더해 검사했다. 생성과 검증은 각각 별도 프로세스에서 측정했다.

| 합성 sources | merged 총 행 | ZIP 생성 | 검증 | 검증 프로세스 최대 RSS | 결과 |
| ---: | ---: | ---: | ---: | ---: | --- |
| 10,000 | 10,018 | 0.048초 | 0.257초 | 52,212 KiB | PASS |
| 100,000 | 100,018 | 0.488초 | 3.109초 | 366,768 KiB | PASS |

모든 행은 정형 검사 후 격리되었다. 각 결과의 수치 및 검사 집계는 [10k JSON](../reports/s1b2-benchmark-10k.json)과 [100k JSON](../reports/s1b2-benchmark-100k.json)에 있다. 이 데이터는 **대부분 source 행에 치우쳐 있으며** 참조·권리·검수 연결이 많은 데이터의 복잡도, DB 적재, 다중 사용자 동시성 또는 실제 D-2 처리 성능을 검증하지 않는다. 해당 범위는 별도 시험이 필요하다.
