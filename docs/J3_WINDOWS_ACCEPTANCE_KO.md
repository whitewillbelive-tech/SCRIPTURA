# J-3 Windows 로컬 실행과 수용 확인

이 안내는 사용자의 **Windows PC에서 직접** D-8 또는 D-9 동결 자료를 여는 방법이다. 현재 개발 환경에서는 실제 Windows 실행을 확인하지 못했으므로 **Windows 실기기 검증은 NOT_RUN**이다. 클라우드의 localhost는 사용자 PC의 주소가 아니다.

## 처음 한 번 준비

1. Windows에 Python 3.10 이상을 설치한다. 공식 Windows 설치 프로그램에서 Python과 **Tcl/Tk**를 함께 설치한다. Python은 이 탐색기에만 사용하며 PostgreSQL, Node.js, 서버 계정은 필요하지 않다.
2. 이 저장소의 `codex/scriptura-j3-d9-private-preview` 브랜치를 PC의 개인 폴더에 내려받아 압축을 푼다. Git을 사용한다면 아래 명령으로 받을 수 있다. 이미 다른 `SCRIPTURA` 폴더가 있다면 덮어쓰지 않도록 새 폴더에서 실행한다.

   ```powershell
   git clone --branch codex/scriptura-j3-d9-private-preview https://github.com/whitewillbelive-tech/SCRIPTURA.git SCRIPTURA-J3
   Set-Location SCRIPTURA-J3
   ```

3. 받은 D-10 인계 ZIP을 Windows 파일 탐색기로 열고 그 안의 `baseline/SCRIPTURA_D9_RESEARCH.zip`만 개인 오프라인 로컬 드라이브의 접근 제한 폴더에 복사한다. D-8도 별도로 받은 고정 ZIP을 선택할 수 있다. 연구 ZIP은 Git 저장소, 공유 폴더 또는 공개 동기화 폴더에 넣지 않는다. 프로그램은 선택한 원본을 변경하지 않는다.

UNC 경로와 URL은 차단된다. 매핑된 네트워크 드라이브나 네트워크 마운트는 프로그램이 완전히 구별할 수 없으므로 직접 오프라인 로컬 드라이브를 선택한다.

## 실행과 종료

`SCRIPTURA-J3` 폴더에서 **`START_SCRIPTURA.cmd`를 두 번 클릭**한다. PowerShell에서 시작하려면 같은 폴더에서 다음 한 줄을 실행한다.

```powershell
.\START_SCRIPTURA.cmd
```

파일 선택 창이 열리면 개인 폴더의 D-9 ZIP 또는 D-8 ZIP을 고른다. 빈 선택은 취소되며 서버가 시작되지 않는다. 자료가 없거나 변조·다른 버전이면 오류를 표시하고 종료하며 합성 예제로 대체하지 않는다. Windows 파일 선택기가 열리지 않으면 Python 설치에서 Tcl/Tk를 확인한다.

콘솔 창에 다른 곳에서 쓰지 않는 추측하기 어려운 **출력 가능 ASCII 20자 이상의 세션 비밀**을 입력한다. 입력 문자는 표시되지 않는다. 브라우저가 열리면 같은 비밀을 화면에 다시 입력한다. 자동으로 열리지 않으면 콘솔에 표시된 루프백 주소를 **같은 PC의 브라우저**에서 직접 연다. 탐색을 마치면 브라우저 탭을 닫고 콘솔에서 `Ctrl+C`를 눌러 종료한다. 인증에 연속 5회 실패하면 서버 전체에서 10초 동안 올바른 비밀도 거부한다.

이 실행기는 선택한 자료 경로를 별도 프로세스 인자나 환경 변수에 넣지 않고 같은 프로세스의 탐색기에 전달한다. 다만 Windows 파일 선택기의 최근 사용 기록, OS 진단 기능과 다른 소프트웨어의 기록까지 제어할 수는 없다. 같은 사용자 프로필·관리자 권한·악성 코드에 대한 완전한 격리는 보장하지 않는다. 공유 계정에서는 사용하지 말고 비밀, 자료 경로, 실제 카드와 원문을 스크린샷·로그·GitHub에 보내지 않는다.

파일 선택기를 사용할 수 없는 경우에만 PowerShell에서 다음 형태를 사용할 수 있다. 경로를 실제 개인 파일 위치로 바꿔야 하며, 이 방식은 **경로가 명령 기록이나 OS 프로세스 목록에 나타날 수 있다**.

```powershell
py -3 scripts\j2_private_preview.py --archive 'C:\개인폴더\SCRIPTURA_D9_RESEARCH.zip'
```

## 내 PC에서 할 수 있는 수용 확인

실제 자료를 캡처하거나 카드의 내용을 전송하지 않고 화면에서만 확인한다.

1. D-9을 선택했을 때 서버가 시작되고 화면이 **D-9 연구 후보**임을 표시하는지 확인한다. 고정 기준본과 무결성 검사에 실패하면 서버는 시작하지 않는다.
2. 자료 단계 D-9와 결과 유형 `claim`을 선택하면 신규 주장 6개가, 같은 단계의 `source`를 선택하면 신규 출처 14개가 나오는지 확인한다. 전체 D-9 후보는 기존 D-8 주장 170개·서지 338개를 보존한 528개다. 개수에 차이가 나면 개인 레코드나 경로를 외부에 보내지 말고 우선 프로그램 실행을 중지한다.
3. 표시가 보류된 이름·제목은 **검색 불가**라는 안내와 일반 조건의 **결과 0건**을 구분해 보여 주는지 확인한다. 미승인 이름·원문·직접 인용·자유 요약·URL은 표시되거나 숨겨진 검색에 사용되지 않아야 한다. 실제 DOI·출판 연도·문헌 위치도 D-8과 D-9 모두 표시 자격 확인 전에는 가리며 해당 값으로 검색하지 않는다.
4. 주장 후보 하나에서 연결 문헌 후보를 열고, 본문 코퍼스와 체계·출처 위치의 가림 상태·귀속과 외부 비판 방향·근거/검증 상태·판본별 권리 9행위가 분리되어 있는지 확인한다. `unknown`과 `conditional`은 이용 허가가 아니다.
5. 필터 변경 또는 초기화 후 이전 선택 내용이 지워지고, 여러 페이지를 이동할 수 있는지 확인한다. 실제 오류를 만들기 위해 외부 사이트나 운영 데이터베이스에 접속할 필요는 없다.
6. 콘솔에서 `Ctrl+C`를 누른 후 화면이 더 이상 새 결과를 불러오지 않는지 확인한다.

위 절차는 사용자의 실제 Windows에서 수행해야 한다. 이 저장소의 자동 시험은 합성 자료로만 실행되며, 클라우드에서 수행된 시험을 Windows 실기기 성공으로 간주하지 않는다. `metadata_candidate`는 검토 후보이며 화면 표시 승인·공식 채택·학술 심사 또는 저작권 허가가 아니다. 현재 Work의 D-9에서 명시적으로 `candidate_visible_local`로 승인된 필드는 없다. Work D-10 결과는 이 단계에 포함되지 않았다.

## 이전 제한의 처리 기록

이전 Work D-9의 자체 보고에는 일시 수신한 파일의 일부 헤더와 Base64 일부가 모델 대화 문맥에 들어갔다는 기록이 있다. 그 내용은 이 저장소·보고서에 재현하지 않는다. 이후 사본을 삭제해도 이미 있었던 전달을 되돌릴 수 없으며, 이 기록만으로 공개 유출이나 법적 침해가 독립적으로 확정된 것은 아니다.

이번 J-3 개발 중에도 별개의 사고가 있었다. D-8 자료 처리 함수의 반환형을 잘못 다뤄 ID·URL·자유 노트·서지 필드가 포함된 연구 메타데이터가 도구 출력으로 나갔다. 원 출력은 약 11,941토큰이었고 모델에는 500토큰 예산에 맞춰 일부만 전달돼 실제 전달된 레코드 수는 확인되지 않는다. 전문이 전달됐다는 증거는 없으며 부분 인용 여부도 확인되지 않았다. 이 문서에는 값·식별자·경로·주소·해시를 재현하지 않는다. 이미 모델 문맥에 전달된 내용은 사후 삭제로 되돌릴 수 없으며, 이 기록만으로 공개 유출이나 법적 침해가 확정된 것은 아니다. 원본을 DB나 저장소에 쓰려는 목적의 작업은 수행하지 않았지만, 공개 변경분에 실제 내용이 남지 않았다는 결론에는 별도 독립 검사가 필요하다. 이 사건으로 `RESEARCH_BOUNDARY` 준수는 **FAIL**이며, 이후 검사에서는 실제 값을 출력하지 않고 메모리 내 집계와 합성 예제만 사용한다.
